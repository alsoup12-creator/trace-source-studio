# 溯源台 Trace Source Studio

一个面向长文档审核的本地溯源工作台：把成品中的段落或观点，与本地文件、网页、专业资料库及 MCP 返回的原文候选放在同一界面中核对，并为 Word 建立“修改—重新溯源—修订副本”的闭环。

> 当前原则：机器负责提取、召回、对齐、分层和提示；人负责判断来源是否充分、结论是否成立，以及是否采纳修改。

## 当前版本能做什么

- 导入 Word、PowerPoint、Excel 或图片成品，按原文段落、工作表行或 OCR 片段展示。
- 使用规则直接分段，也可让 4B 以下本地模型对程序预切出的原文编号进行语义组合；程序校验顺序、覆盖率和原文一致性，失败内容自动规则兜底。
- 从指定本地文件夹检索文档、表格、PDF、文本和图片 OCR，并保留文件名、页码、段落或单元格位置。
- 可选接入网页搜索、秘塔 Search、北大法宝 MCP 和通用 Streamable HTTP MCP，统一展示为可复核的来源候选。
- 候选先由规则宽召回；可选本地小模型把候选分成“主要候选、可能冲突、其他线索”。模型只分层，不删除候选。
- Word `.docx` 可在中间栏修改文字，清空修改前依据后重新溯源，再在原文件夹生成 Microsoft Word 原生修订副本。只修订实际变化的字符，原件不覆盖。

## 一次完整操作

1. 导入已经形成的成品文件。
2. 直接使用原始段落，或点击“本地 AI 智能细分”。
3. 在中间栏选中当前要审核的段落或观点。
4. 如有需要，在左栏围绕这个段落询问含义、风险点、核对方向或修改建议。
5. 选择来源范围：本地文件夹、网站、通用 MCP 或北大法宝。
6. 执行当前段落溯源或批量溯源，在右栏核对候选原文与原始位置。
7. 可选启用本地 AI 精筛，把宽召回结果分层；所有候选仍然保留。
8. 对 Word 文字进行人工修改后，旧候选和旧问答进入审计历史，新文字重新执行溯源。
9. 生成同路径、带时间戳的 Word 原生修订副本；原件始终保持不变。

## 三栏分别负责什么

### 左栏：只针对当前段落的对话

左栏的 API/MCP 对话只接收“当前选中的段落 + 用户当前问题”，用于基本查询和建议，例如：

- 解释这段话表达的含义；
- 提示可能遗漏的条件、例外、数字或主体；
- 给出进一步核对方向或检索关键词；
- 提供修改建议，供用户人工选择。

它目前不是全篇写作代理，不会自动遍历全文，不会直接改写中间栏文字，也不会替代右栏的来源核验。对话历史按段落保存。

当前可选对话通道包括 OpenAI 兼容 API、秘塔问答、通用 MCP 和北大法宝。各供应商实际能力取决于接口权限、工具定义和返回格式。

### 中间栏：成品原文与人工修改

- 展示原始段落、语义细分结果、工作表行或 OCR 文字。
- 用户在这里选择审核单元，并可对 Word `.docx` 的文字进行人工修改。
- 修改前的候选、问答和核对结果会进入审计历史；修改后的文字不会沿用旧依据。

### 右栏：来源候选与原文定位

- 展示本地文件、OCR、网页、法律法规和 MCP 资料库返回的候选。
- 区分逐字命中、规范化命中、关键词组合、观点近似和关联线索。
- 主要候选与可能冲突默认展开，其他线索折叠保留，以兼顾“不遗漏”和“不过度干扰”。
- PDF 候选支持在工作台内按命中页阅读，也可使用系统默认程序打开原文件。

## 文件类型

| 文件类型 | 作为待审核成品导入 | 作为本地来源检索 | 修改与修订副本 | 当前处理方式 |
| --- | --- | --- | --- | --- |
| `.docx` | 支持 | 支持 | 支持 | 按 Word 段落提取；字符级原生修订写回 |
| `.pptx` | 支持 | 支持 | 不支持 | 按幻灯片文本提取与溯源 |
| `.xlsx` / `.xlsm` | 支持 | 支持 | 不支持 | 按工作表非空行展示，保留单元格范围；不执行宏 |
| `.png` / `.jpg` / `.jpeg` / `.bmp` / `.tif` / `.tiff` / `.webp` | 支持 | 支持 | 不支持 | OCR 后按文字片段溯源 |
| `.pdf` | 暂不作为主成品导入 | 支持 | 不支持 | 文本 PDF 按页提取；扫描 PDF 可选 OCR |
| `.txt` / `.md` / `.csv` / `.json` / `.html` / `.htm` / `.xml` | 暂不作为主成品导入 | 支持 | 不支持 | 作为本地文字来源分段检索 |
| `.doc` / `.xls` | 不支持 | 不支持 | 不支持 | 请先另存为 `.docx` / `.xlsx` |

说明：Excel 公式只读取工作簿中保存的公式文本和缓存值；不会打开或执行宏。OCR 结果属于待核对文本，不应代替原图。Word 修订要求 Windows 已安装 Microsoft Word 和 `pywin32`。

## 本地 AI 的角色

本地模型是可选的语义辅助层，不负责决定证据或写回位置：

1. **智能细分**：程序先把原文切成稳定编号，本地模型只组合相邻编号；程序负责原文重建和漏项兜底。
2. **检索词扩展**：强候选不足时，生成少量同义词、专业术语或固定表达，再交给确定性检索。
3. **候选精筛**：比较当前观点和少量候选原文，辅助区分直接对应、部分对应、可能冲突和弱相关。
4. **本地材料核对提示**：只根据当前段落与已经命中的本地原文提示不一致、未覆盖或材料不足。

这些任务经过约束后可在 2B–4B 指令模型上尝试。评估重点不是语言是否流畅，而是漏组率、规则兜底率、冲突识别和原文引用是否准确。

## API 与 MCP：当前能力

- **OpenAI 兼容 API**：用于当前段落问答，以及可选的观点结构化辅助。
- **本地 OpenAI 兼容接口**：适配 LM Studio、Ollama 等，用于智能细分、检索词扩展、候选精筛和本地核对提示。
- **秘塔 Search / 问答**：搜索网页候选、辅助生成检索问题，并可按需深读候选网页。
- **北大法宝 MCP**：支持法规关键词、法规语义和精准法条检索；默认优先现行有效结果。
- **通用 MCP**：当前配置一个 Streamable HTTP 地址和工具名，按当前段落及补充 Prompt 调用，并将返回结果转换为统一候选。

API Key 和 Token 不写入项目文件，当前界面输入默认只保存在进程内存中；也可以通过环境变量提供。不同供应商的鉴权、参数和响应结构仍可能需要单独适配。

## 后续可以开发什么

现有 API 与 MCP 接口保留的是“能力插槽”，后续可以沿以下方向继续扩展：

### 1. 从段落问答发展为受控审核代理

- 让接口按用户确认的清单逐段检查主体、数字、日期、条件、例外和引用；
- 把建议转换成结构化待办，而不是直接改文档；
- 用户逐项确认后，再进入修改、重新溯源和修订副本流程；
- 为每一步记录所用模型、提示、来源和人工决定，形成可审计链路。

### 2. 更完整的 MCP 资料生态

- 同时配置多个 MCP 服务，并自动发现可用工具及参数结构；
- 接入法规库、案例库、企业知识库、项目档案、邮件或协作平台；
- 建立供应商适配器，把不同响应统一为带原文和位置的 Candidate；
- 增加权限范围、数据外发提示、失败回退和调用审计。

### 3. 更强的本地检索与证据组织

- 增加本地向量索引，补充同义表达和跨文件近似召回；
- 建立实体、日期、金额、义务和例外条件的结构化索引；
- 在不删除原始候选的前提下，形成证据包、冲突表和缺口清单；
- 支持“展开同文件更多结果”，在候选多样性和完整性之间切换。

### 4. 扩展修订闭环

- 支持表格单元格、页眉页脚、脚注、批注和更复杂 Word 对象的安全定位；
- 评估 PowerPoint 和 Excel 的可审计修改副本；
- 增加修改提议、人工接受/拒绝、重新溯源状态和版本比较；
- 输出可归档的审核报告与来源目录。

### 5. 合规与规模化

- 增加本地、在线和混合处理策略，明确哪些字段允许发送给哪个接口；
- 支持敏感信息识别、脱敏占位和本地回填；
- 增加模型与接口白名单、权限审批、日志留存和项目隔离；
- 建立真实材料评测集，持续统计召回率、无关候选率、冲突发现率和定位成功率。

无论接入多强的模型或资料库，原文、位置、规则兜底、候选保留和人工决定仍应保持独立。

## 安装与启动

建议使用 Windows 与 Python 3.10+：

```powershell
python -m pip install -r requirements.txt
```

然后双击 `启动溯源台.cmd`。安装 `pywebview` 后使用独立 WebView2 窗口；否则回退到默认浏览器。

### 可选 CPU OCR

```powershell
python -m pip install -r requirements-ocr.txt
```

还需要安装 Tesseract 与 `chi_sim` 中文语言包。

### 可选 NVIDIA CUDA OCR

以 Windows + CUDA 12.6 为例：

```powershell
python -m pip install paddlepaddle-gpu==3.2.0 -i https://www.paddlepaddle.org.cn/packages/stable/cu126/
python -m pip install -r requirements-ocr-cuda.txt
```

GPU 仅用于图片和扫描 PDF OCR，不参与普通 Word、PowerPoint、Excel、文本 PDF 的提取或索引检索。

## 安全边界

- 原件默认只读；只有用户保存 Word 修改并点击“生成修订副本”时才创建新文件。
- 输出前重新校验原件 SHA-256、段落序号、原始文字和片段坐标；不能唯一定位时停止写入。
- 工具不判断观点正确、法律依据充分、法规适用或计算正确。
- 搜索摘要和模型概括不能冒充来源逐字原文。
- 本地索引和项目记录默认保存在 `%LOCALAPPDATA%\TraceSourceStudio`，不纳入 Git。
- 本地材料默认不发送给在线接口；涉及在线总结时应由用户明确开启并确认范围。

更详细的层级、Candidate 数据结构和实施边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
